This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Website for "Hej Kombucha", a Swedish kombucha company in Örebro. All user-facing
content is in Swedish.

This is a **SvelteKit 2 / Svelte 5** app. The visual design comes from the owner's
Claude Design project "Hej Kombucha Design System" (`templates/website/Website.dc.html`),
ported by hand to Svelte + Tailwind. `html-version/` is the _previous_ static site — a
legacy reference only, not built or served, and no longer the visual source of truth.

The marketing pages (home, `/stores`, `/about`, `/bli-aterforsaljare`) and the blog live
under the `src/routes/(site)/` route group, which wraps them in shared `Header`/`Footer`
(`src/lib/components/`). `/admin` sits outside that group so it renders chrome-free.

## Commands

Package manager is **Bun** (`bun.lock`, `engine-strict=true`). Use `bun` / `bunx`.

```sh
bun install
bun run dev        # vite dev server
bun run build      # production build (adapter-node)
bun run preview    # serve the production build
bun run check      # svelte-kit sync + svelte-check (type checking)
bun run lint       # prettier --check . && eslint .
bun run format     # prettier --write .

bun run db:start   # local Postgres via compose.yaml on :5433 (needs Docker; 5432 is taken by a native PG 17 on the dev box)
bun run db:push    # push schema.ts straight to the DB (dev)
bun run db:generate / db:migrate   # SQL migrations (prod)
bun run db:studio  # Drizzle Studio
bun run auth:schema  # regenerate Better Auth tables into src/lib/server/db/auth.schema.ts
bun run seed:admin <mail> "<name>" <password>   # first admin, or reset an existing password
```

No test framework is configured. There is no single-test command.

## Architecture

- **Framework**: SvelteKit 2 with Svelte 5 runes (`$props`, `$state`, `$derived`, `{@render ...}`).
  Deployed via `@sveltejs/adapter-node` in Docker (`Dockerfile`), hosted with Coolify.
- **Styling**: Tailwind CSS 4 via the `@tailwindcss/vite` plugin (no `tailwind.config.js`;
  config is CSS-first in `src/app.css`). `app.css` defines the brand design system in a
  Tailwind `@theme` block — colors `brand` (#f24440), `brand-ink`, `brand-tint`, `cream`
  (#f3f5f0, "paper"), `ink` (#111), `charcoal` (#333), `muted`; fonts `display`
  (Space Grotesk) / `body` (Roboto Mono); an `xs` breakpoint — plus component classes
  `.btn` (`-primary`/`-secondary`/`-inverse`/`-link`, `-sm`/`-lg`), `.kicker`, `.tag`,
  `.card`, `.chip`, `.field`, `.check`, `.divider`, `.link`, `.social`, `.markdown`.
  The brand is flat and square: 1.5px ink hairlines (`--hkb-line`), no radius, no shadow.
  Note: a stray/malformed CSS comment before `@theme` silently disables the whole block.
- **Header**: the mobile menu lives _outside_ `<header>` on purpose — `backdrop-filter` on the
  header would otherwise make it the containing block for the `fixed` overlay.
- **Markdown**: `mdsvex` (configured in `svelte.config.js`) processes `.md`/`.svx`.
  `.md` and `.svx` are registered as Svelte component extensions, so markdown files
  compile to components.

### Database, forms & admin

- **Database**: Postgres via **Drizzle** (`drizzle-orm` + `postgres` driver). Client in
  `src/lib/server/db/index.ts` reads `DATABASE_URL` from `$env/dynamic/private` at _runtime_,
  so the Docker build needs no DB. Schema in `src/lib/server/db/schema.ts`: `subscribers`
  (newsletter, `email` unique) and `retailer_applications` (`status`: ny / kontaktad / klar).
  Better Auth's tables (`user`, `session`, `account`, `verification`) live in
  `auth.schema.ts`, generated by `bun run auth:schema` and re-exported from `schema.ts` —
  regenerate, don't hand-edit. Local dev DB: `compose.yaml` → `bun run db:start`, then
  `bun run db:push`.
- **Forms**: the newsletter form (`ContactForm.svelte`, used on `/` and `/about`) posts to a
  shared `subscribe` action in `src/lib/server/subscribe.js`, re-exported by each page's
  `+page.server.js`. `/bli-aterforsaljare` has its own `apply` action. Both use `use:enhance`
  and a hidden `website` honeypot field (filled = bot → pretend success, store nothing).
- **Mail**: `src/lib/server/mail.ts` wraps **Resend**. `notify()` mails the brewery
  (best-effort, never fails the form), `addContact()` mirrors a subscriber into the Resend
  segment, `sendNewsletter()` creates + sends a Broadcast to `RESEND_SEGMENT_ID`. Resend v6
  uses _segments_ (audiences are deprecated). With no `RESEND_API_KEY` mail is logged to the
  console so local dev works without an account.
- **Admin** (`/admin`): **Better Auth** (email + password, `better-auth/minimal`, Drizzle
  adapter). Config in `src/lib/server/auth.ts`; `src/hooks.server.ts` resolves the session into
  `locals.user` and redirects unauthenticated `/admin/*` to `/admin/login` — the guard lives in
  the hook on purpose, since form actions run _before_ layout `load`. Public sign-up is
  disabled: the `user` table is the allowlist. First admin: `bun run seed:admin <mail> "<name>"
<password>` (`scripts/seed-admin.ts` runs outside SvelteKit, so it builds its own DB client
  from `process.env`). Further admins are invited from `/admin`: `createAdmin()` in
  `src/lib/server/admins.ts` creates the account with a random password, then Better Auth's
  `requestPasswordReset` mails a set-password link to `/admin/set-password` (24 h). The same
  link powers "Glömt lösenord?" on `/admin/login`. Admin lists subscribers, retailer
  applications (with status), admins, and sends newsletters (explicit confirm checkbox).
  Sveltia CMS was removed — there is no git-based CMS anymore.
- **Env vars** (see `.env.example`): `DATABASE_URL`, `BETTER_AUTH_SECRET`, `RESEND_API_KEY`,
  `RESEND_SEGMENT_ID`, `RESEND_FROM` (must be on a domain verified in Resend), and `ORIGIN` —
  used both as Better Auth's `baseURL` (reset links are built from it) and as SvelteKit's CSRF
  origin; behind a proxy it is mandatory or every form POST is rejected. The Dockerfile sets a
  default `ORIGIN`; Coolify can override it.

### Blog (markdown content pipeline)

- Posts are markdown files with YAML frontmatter in `src/content/blog/`,
  named `YYYY-MM-DD-slug.md` (fields: `title`, `date`, `description`, `image`, body).
- `src/routes/(site)/blog/+page.js` builds the index by eagerly globbing
  `import.meta.glob('../content/blog/*.md')`, reading each file's `metadata`, and
  sorting by date descending.
- `src/routes/(site)/blog/[slug]/+page.js` dynamically `import()`s the matching markdown
  file by slug; missing slug → `error(404)`.
- mdsvex applies `src/lib/components/BlogLayout.svelte` to rendered posts.
- The blog nav link is commented out in `Header`/`Footer` — the blog is dormant, not removed.

## Conventions

- `bun run lint` enforces Prettier (incl. `prettier-plugin-svelte` and
  `prettier-plugin-tailwindcss` for class sorting) plus ESLint. Run `bun run format`
  before committing.
- Path alias `$lib` → `src/lib`. Server-only code goes in `src/lib/server/`.
- New routes follow SvelteKit file-based routing under `src/routes/`; static assets
  served from `static/` at the site root. Design-system images referenced by the site
  live in `static/images/` (bottle cutouts `bottle-*.png`, store photos, logo `hkb2026.png`).
- Never write to `.env*` from tooling — they are deny-listed. Tell the user what to add instead.
